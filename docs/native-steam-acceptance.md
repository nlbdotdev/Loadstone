# Native TTW Steam-client acceptance

On October 13, 2026, the private 0.4.0 portable was exercised against the isolated TTW installed-baseline candidate described in the platform's reconstruction record. This was a real local-client check, separate from synthetic Electron tests. It did not install from public provider downloads or certify a clean Windows environment.

- Portable SHA-256: `2780774686a6c8a9cc73f1cd36fb64dbaaad8c9af523847bb5398d2787b3112d`.
- Embedded source: `d2bc450ab7df0b95467f191547d7852d30256473`; merged source `c80e996fb1466f45c27b8bbc50a12f9749e37d06` has the same tree.
- Candidate recipe SHA-256: `a76e91b75ab3aaeb2efcdec0803cde822ec94ed40ee382f49f0ae6dd82a740dd`; private version `2026.10.13-local`.
- MO2 `2.5.2-ML1.5`, selected profile `Tale of Two Wastelands`, candidate-local game, mods, profiles, saves and writable folders.

## Observed results

1. The actual portable verified all 13,952 recipe outputs, displayed the candidate review and persisted explicit library admission in isolated application data.
2. Saving a Steam entry while the real client was running returned the expected instruction to exit Steam. The shortcuts file remained unchanged.
3. After a normal Steam exit, Loadstone created one owned entry and its backup. All three existing shortcut records remained byte-for-byte identical. The new executable, working directory and arguments selected only the candidate's MO2/profile.
4. Reopened Steam displayed the entry. Play started the candidate's actual MO2 process with the declared arguments.
5. MO2 displayed its game-edition chooser. Selecting Steam wrote `General/game_edition=Steam`, then started the candidate's `Game/FalloutNV.exe`. The TTW main menu and Steam overlay notice were observed. This required intervention and is **not** a successful one-click launch.
6. Steam was configured to record in the background to a known folder, with microphone off and game audio only. Its renderer log reported starting recording, but no new video or clip appeared in the configured location or the prior default recording location. The instant-clip hotkey produced no verified clip. The session ended at the menu; no gameplay or recording success is claimed. The prior audio source was restored afterward.
7. Game and manager exited. All 18 previously fingerprinted original-profile/global-save files remained unchanged, with no added files under those roots. The candidate created an empty local saves folder; no save was loaded or created. Candidate configuration/profile writes remain private, with before/after evidence retained.

## Follow-up and limits

The generator previously omitted the edition field present in the installed source configuration. The optional, validated `gameEdition` recipe declaration addresses that missing field without silently changing legacy generated bytes or receipt fingerprints. Recipes using it are new recipe identities. Unit/integration checks cover storefront consistency, mixed-store TTW requirements, old output identity and launch-time drift checks; synthetic Electron flows exercise the extended declaration. This source change is newer than the tested 0.4.0 portable above.

A fresh candidate built with the revised declaration still needs an uninterrupted real launch. Diagnose recording and inspect a short game-video sample before longer play; do not substitute desktop capture. New-game/save/reload, controller input, mod behavior, maintenance after actual play, Desktop launch and clean-machine/provider acceptance remain open. No runtime support claim follows from the GOG declaration validator. Featured-pack source completion, permissions and publication are separate gates.

Private evidence is retained under the ignored `test-results/native-acceptance/ttw-recorded/` directory. It contains local paths and account-specific shortcut backups and must not enter public archives. No game footage was produced for publication.
